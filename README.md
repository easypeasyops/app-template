# app-template

[![CI](https://github.com/easypeasyops/app-template/actions/workflows/ci.yml/badge.svg)](https://github.com/easypeasyops/app-template/actions/workflows/ci.yml)

A minimal Python service with everything
[easypeasyops/platform](https://github.com/easypeasyops/platform)'s app contract needs,
filled in and proven by this repo's own CI. Start a new app from it instead of copying
pieces out of the existing apps.

`app-template` is the one placeholder: it is this repo's name and the app's name.

## What's here

| Path | What | The contract |
| --- | --- | --- |
| `apps/app-template/app/` | The service: `/`, the probes, request metrics | `/healthz` and `/readyz` on port 8000; `/metrics` on 9100 with `http_requests_total` and `http_request_duration_seconds` |
| `apps/app-template/Dockerfile` | The image | Runs as UID 10001, writes nothing to its filesystem (the chart mounts the root read-only), stops on SIGTERM. `scripts/smoke.sh` proves it |
| `apps/app-template/deploy/service/values.yaml` | The app's values for the platform's service chart | Its name and `image.repository: ghcr.io/easypeasyops/<repo>/<app>` |
| `apps/app-template/deploy/envs/<env>.yaml` | Each environment's settings and the release it runs (`image.digest`) | One file per environment; the namespace is `<app>-<env>` |
| `apps/app-template/deploy/prometheus/slos.yaml` | The SLO spec; `deploy/service/slo-rules.values.yaml` is generated from it | Generated by the platform's `scripts/gen_slo_rules.py` at `platform.lock`'s commit |
| `.github/workflows/ci.yml` | CI: the platform's reusable workflows (lint, types, tests; image build, scan, smoke test), the SLO rules checked against their spec, every environment rendered with the service chart and schema-checked | Workflows pinned by the platform's commit SHA; `ci` is the one required check |
| `.github/workflows/release.yml` | An `<app>/vX.Y.Z` tag builds, scans, pushes and attests the image | The provenance's signer must be this repo's own `release.yml`, at the app's tag: don't rename or move it |
| `platform.lock` | The platform commit CI runs against | The same SHA as in `ci.yml` (a test checks) |
| `.github/renovate.json5`, `.github/dependabot.yaml` | Keep the pins current | Renovate: the platform commit. Dependabot: actions, Python dependencies, base images |

## Start an app from it

1. Create the repo: `gh repo create easypeasyops/<app> --public --template easypeasyops/app-template --clone`.
2. Rename, from the repo's root:

   ```bash
   git mv apps/app-template apps/<app>
   git grep -lz app-template | xargs -0 perl -pi -e 's/app-template/<app>/g'
   (cd apps/<app> && uv lock)
   ```

   Then regenerate the SLO rules (the command is at the top of
   `apps/<app>/deploy/prometheus/slos.yaml`), commit and push. An app name is lowercase
   letters, digits and dashes. In a repo that holds several apps the image is
   `ghcr.io/easypeasyops/<repo>/<app>`: fix `image.repository` by hand.
3. On GitHub: make `ci` a required check on `main`, and add the repo to the Renovate app.
4. Release it: tag the commit `<app>/v0.1.0` (the version in `apps/<app>/pyproject.toml`)
   and push the tag. The release's notes hold the image's digest: set it as `image.digest`
   in `deploy/envs/staging.yaml`.
5. In the platform repo, add `apps/<app>/` (its README, "Onboarding an app"). Argo CD then
   deploys staging; promote to prod by setting the same digest in `deploy/envs/prod.yaml`.

What the app still decides:

- **Its name**, and so its namespaces (`<app>-staging`, `<app>-prod`) and image.
- **Its hostnames**: `gateway.hostnames` in each environment's file.
- **Its SLOs**: the objectives and the latency threshold in `slos.yaml`, and the runbook
  its alerts link to.
- **Its environment**: the `env` list in `values.yaml`; keys that can't be in git come from
  a store the platform holds for the app (`secretEnv`).
- What else it needs from the chart: a database, Redis, workers, cron jobs, autoscaling,
  canary releases. The chart's
  [values.yaml](https://github.com/easypeasyops/platform/blob/main/charts/service/values.yaml)
  documents each.

## Develop

From `apps/app-template`:

```bash
uv run pytest                 # tests, with coverage
uv run ruff check . && uv run mypy app tests
docker build -t app-template:dev . && scripts/smoke.sh
```

## SLO burn-rate alerts

The SLO alerts' runbook link points here until the app has a runbook of its own. An alert
names the SLO (`slo` label) and the namespace; it fires when the error budget is being
spent faster than the objective allows. Start from the platform's SLO dashboard in
Grafana (traffic, errors and latency by route), then the app's logs.
